# 附录 E：能力系统形式化语义

> 本附录从形式化角度描述 Pony++ 的引用能力系统，适合深入研究语言设计的读者。

---

## E.1 能力集合

Pony++ 定义 6 种引用能力，记作集合 **C** = {`iso`, `trn`, `ref`, `val`, `box`, `tag`}。

每个能力由三个属性决定：

| 属性 | 含义 | 取值 |
|------|------|------|
| **可变性** (Mutability) | 能否修改引用的数据 | 可变 / 不可变 |
| **共享性** (Shareability) | 能否在多个 Actor 间共享 | 可共享 / 不可共享 |
| **可发送性** (Sendability) | 能否作为消息发送 | 可发送 / 不可发送 |

---

## E.2 能力属性矩阵

| 能力 | 可变性 | 共享性 | 可发送性 | 说明 |
|------|--------|--------|----------|------|
| `iso` | 可变 | 不可共享 | 可发送 | 独占引用，发送时消耗 |
| `trn` | 可变 | 不可共享 | 可发送 | 可转移引用 |
| `ref` | 可变 | 不可共享 | 不可发送 | 局部可变引用 |
| `val` | 不可变 | 可共享 | 可发送 | 不可变共享 |
| `box` | 不可变 | 可共享 | 不可发送 | 共享只读 |
| `tag` | 不可变 | 可共享 | 可发送 | 仅身份，无数据访问 |

---

## E.3 子类型关系

能力之间的子类型关系（`<:` 表示"是子类型"）：

```
iso <: trn <: box <: tag
ref <: box <: tag
val <: box <: tag
```

图示：

```
        tag
         ↑
        box
       / | \
     iso ref val
      ↑
     trn
```

**规则**：

1. `iso` 是 `trn` 的子类型（独占引用可当作可转移引用使用）
2. `ref`、`val`、`trn` 都是 `box` 的子类型
3. `box` 是 `tag` 的子类型
4. `iso` 和 `ref` 之间没有子类型关系

## E.4 发送时的自动转换

当数据通过 `be` 方法作为消息发送时，编译器自动进行能力转换：

| 原始能力 | 发送后 | 条件 |
|----------|--------|------|
| `ref` | `val` | 自动转换（发送后原引用失效） |
| `iso` | `iso` | 保持（消耗原引用） |
| `trn` | `val` | 自动转换 |
| `val` | `val` | 保持 |
| `box` | `tag` | 自动转换（丢失数据访问） |
| `tag` | `tag` | 保持 |

**核心保证**：发送后，发送方不再持有可变引用。这消除了数据竞争。

## E.5 形式化规则

### E.5.1 引用有效性

设 Γ 为类型环境，e 为表达式，c 为能力。引用有效的前提是：

```
Γ ⊢ e : c  ⇒  e 在当前作用域内有效
```

### E.5.2 消耗（Consume）

`iso` 和 `trn` 引用在发送后被消耗（不能再使用）：

```
consume(iso) → 引用失效
consume(trn) → 引用失效
consume(ref) → 引用转为 val
```

### E.5.3 共享（Share）

`val` 和 `box` 引用可以在多个 Actor 间共享：

```
share(val) → 多个 Actor 可同时读取
share(box) → 多个 Actor 可同时读取（同一 Actor 内）
```

## E.6 安全性定理

**定理 1（无数据竞争）**：如果程序通过类型检查，则不存在两个 Actor 同时对同一数据进行读写。

**证明思路**：

1. 可变数据（`ref`）不能跨 Actor 发送
2. 发送时 `ref` 自动转为 `val`（不可变）
3. `iso` 发送后消耗，原 Actor 不再持有
4. 因此，任何时刻最多有一个 Actor 持有可变引用

**定理 2（无死锁）**：Pony++ 的 Actor 模型不支持同步等待，因此不会出现死锁。

**证明思路**：

1. `be` 方法是异步的，不等待执行完成
2. Actor 之间没有同步调用
3. 没有锁机制
4. 因此，不存在循环等待

## E.7 与其他系统的比较

| 系统 | 机制 | 优势 | 劣势 |
|------|------|------|------|
| Pony++ | 编译期能力检查 | 零运行时开销 | 学习曲线陡峭 |
| Rust | 所有权 + 借用 | 内存安全 | 仅限单线程 |
| Erlang | 运行时隔离 | 简单易用 | 运行时开销 |
| Go | Channel + Mutex | 简单 | 需要手动管理锁 |

Pony++ 的独特之处：**编译期保证并发安全，零运行时开销**。

## 一、项目背景与愿景

### 1.1 背景

当前并发编程领域存在三个难以兼得的方向：

| 语言/系统 | 优势 | 短板 |
|-----------|------|------|
| Pony | 引用能力（Reference Capabilities）在编译时消除数据竞争；每 Actor 独立 GC，无全局 STW；Actor 模型天然适配并发 | 不原生支持 WebAssembly；生态较小 |
| Erlang/OTP | 监督树提供工业级容错；百万级轻量进程；热代码升级 | 运行时较重；性能不如系统级语言 |
| WebAssembly | 通用沙箱；跨平台；组件模型解决模块间互操作 | 缺乏原生 Actor 模型支持；GC 支持尚在完善中 |

Pony++ 的愿景是：融合 Pony 的类型安全 + Erlang 的容错体系 + WebAssembly 的通用沙箱，打造一个"天生云原生"的新一代编程语言。

### 1.2 核心设计目标

| 目标 | 说明 | 可验证指标 |
|------|------|-----------|
| 编译时数据竞争自由 | 继承 Pony 的引用能力系统，在编译期保证无数据竞争 | ThreadSanitizer 零警告 |
| Actor 模型作为一等公民 | 每个 Actor 是独立的 Wasm 模块或组件，拥有自己的堆、栈和消息队列 | Actor 创建延迟 < 100μs |
| Erlang 风格监督树 | 内置 Supervisor 机制，实现"Let it crash"容错哲学 | 进程崩溃恢复 < 10ms |
| 原生 Wasm 沙箱 | 编译产物为 Wasm 组件，运行在任何支持 WASI 的宿主上 | WASI Preview 2 兼容 |
| M:N 调度 | M 个 Actor 映射到 N 个系统线程，工作窃取调度器 | 线程利用率 > 85% |
| 热代码升级 | 借鉴 Erlang，支持不停机更新 Actor 行为 | 升级期间零请求丢失 |
| 跨平台 | 同一 Wasm 二进制运行在浏览器、服务器、边缘 | 单一构建产物 |

### 1.3 非目标

- 不追求极致性能——Wasm 有固有开销，目标是在安全与性能间取得平衡
- 不做完全兼容 Pony——这是新的语言，不是 Pony 的移植
- 不做完全兼容 Erlang——借鉴监督树思想，但不兼容 Erlang 语法/生态
- 不取代操作系统——定位在应用层并发编程

### 2.3 架构设计原则

1. **编译时安全优先**：引用能力系统在编译期执行，运行时不牺牲性能
2. **Wasm 原生**：编译目标就是 Wasm 组件，不是翻译为 Wasm 的中间态
3. **渐进式运行时**：从单线程协作调度到 M:N 工作窃取，按需启用
4. **可观测性内置**：每个 Actor 有生命周期事件日志，监督树有诊断接口
5. **向后兼容**：WIT 接口版本化，旧组件可在新运行时运行

## 三、核心模块详细设计

### 3.1 引用能力系统

Pony++ 完整继承 Pony 的六种引用能力，并增加 sendable 属性和跨组件序列化规则。

#### 3.1.1 能力定义

| 能力 | 含义 | 可变性 | Sendable | 跨组件规则 |
|------|------|--------|----------|-----------|
| `iso` | 唯一可变引用 | 可变 | ✅ 是 | 发送后变为 `box`（消费语义） |
| `trn` | 转移引用 | 可变 | ❌ 否 | 不可发送，仅同 Actor 内传递 |
| `ref` | 本地可变引用 | 可变 | ❌ 否 | 不可发送 |
| `val` | 全局不可变 | 不可变 | ✅ 是 | 可直接发送（值复制） |
| `box` | 本地只读 | 不可变 | ❌ 否 | 不可发送，仅同 Actor 内读取 |
| `tag` | 仅标识 | 不可变 | ✅ 是 | 可发送（引用句柄） |

#### 3.1.2 能力转换规则

```
iso ──发送──▶ box (消费)
iso ──转移──▶ trn (同 Actor 内)
iso ──不可变──▶ val

trn ──发送──▶ ❌ 编译错误
trn ──释放──▶ ref (同 Actor 内)

ref ──发送──▶ ❌ 编译错误

val ──发送──▶ val (值复制)
val ──不可变──▶ tag

box ──发送──▶ ❌ 编译错误

tag ──发送──▶ tag (引用句柄)
```

#### 3.1.3 跨组件序列化协议

当 Actor 跨 Wasm 组件边界通信时，编译器自动插入序列化/反序列化逻辑：

```
┌─────────────────────────────────────────────────────────────┐
│              跨组件消息传递协议                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Sender (组件A)                    Receiver (组件B)         │
│  ┌─────────────┐                   ┌─────────────┐         │
│  │ Actor A     │                   │ Actor B     │         │
│  └─────────────┘                   └─────────────┘         │
│         │                                ▲                  │
│         │ 1. 调用 WIT 接口               │                  │
│         │ ──────────────────────────────▶│                  │
│         │                                │                  │
│         │ 2. 序列化器检查能力            │                  │
│         │    iso → 消耗并序列化          │                  │
│         │    val → 值复制序列化          │                  │
│         │    tag → 句柄序列化            │                  │
│         │    trn/ref/box → 拒绝发送     │                  │
│         │                                │                  │
│         │ 3. 消息入队 + 唤醒            │                  │
│         │ ──────────────────────────────▶│                  │
│         │                                │                  │
│         │ 4. 反序列化器重建              │                  │
│         │    (类型检查 + 能力恢复)        │                  │
│         │                                │                  │
└─────────────────────────────────────────────────────────────┘
```

序列化格式（自定义二进制协议）：

```
┌────────────┬────────────┬─────────────────┬─────────────────┐
│ 消息头     │ 能力标记    │ 类型标记         │ 数据载荷        │
│ 8 bytes   │ 1 byte     │ 1 byte          │ variable        │
└────────────┴────────────┴─────────────────┴─────────────────┘

消息头:
  - version: 2 bytes (当前 = 0x0001)
  - actor_id: 4 bytes
  - method_id: 2 bytes

能力标记:
  0x01 = iso (消费)
  0x02 = val (值复制)
  0x03 = tag (句柄)
  0xFF = 错误 (不可发送类型)
```

### 3.2 Actor 模型

#### 3.2.1 基础语法

```pony
// Pony++ 示例：Counter Actor
actor Counter(val initial: U64 = 0) {
  var count: U64 = initial

  // 构造函数
  new create(initial: U64) =>
    count = initial

  // 有返回值的方法（可在同 Actor 内同步调用）
  fun value(): U64 =>
    count

  // 无返回值的消息（异步发送）
  be increment() =>
    count = count + 1

  // 有返回值的行为（异步 + 回复）
  be get(ref reply: Reply[U64]) =>
    reply(count)
}
```

#### 3.2.2 Actor 生命周期

```
┌─────────┐    new create()    ┌──────────┐    消息到达    ┌──────────┐
│ 不存在  │ ──────────────▶    │ 初始化    │ ───────────▶ │ 运行中   │
│         │                    │          │              │          │
└─────────┘                    └──────────┘              └──────────┘
                                    │                         │    │
                                    │ 失败                   │    │ 消息处理中
                                    ▼                         │    ▼
                               ┌──────────┐              ┌──────────┐
                               │ 已销毁   │ ◀────────────│ 已停止   │
                               │          │    停止      │          │
                               └──────────┘              └──────────┘
                                                          │
                                                          │ 异常崩溃
                                                          ▼
                                                   ┌──────────┐
                                                   │ 已崩溃   │
                                                   │ (待重启) │
                                                   └──────────┘
```

Actor 寻址模型：

```pony
// Actor 地址 = 组件实例 ID + Actor ID
// 同组件内: 直接 Actor 引用 (tag)
// 跨组件: 远程引用 (含序列化数据)

actor main() {
  new create() =>
    // 同组件：直接引用
    let counter: Counter = new Counter(0)
    counter.increment()

    // 跨组件：需要消息传递
    let remote: tag RemoteCounter = RemoteCounter.create()
    remote.increment()  // 发送消息
}
```

#### 3.2.3 消息传递语义

| 语义 | 说明 | 保证 |
|------|------|------|
| at-most-once | 消息可能丢失 | 不保证 |
| at-least-once | 消息可能重复 | 不丢失 |
| exactly-once | 消息恰好一次 | ✅ Pony++ 提供 |

Pony++ 默认使用 exactly-once 语义：
- 消息在发送前被分配唯一 ID
- 接收方在处理后确认
- 未确认的消息由发送方重传
- 接收方通过消息 ID 去重

### 3.3 监督树

#### 3.3.1 语言级语法

```pony
// 监督树声明
actor RootSupervisor() {
  // 监督策略声明
  supervisor(
    strategy = one_for_one,
    max_restarts = 5,
    interval = 60,  // 秒
    restart_intensity = "exponential"  // 指数退避
  )

  new create() =>
    // 启动子 Actor 并设置监督
    let counter = new Counter(0)
    supervise(counter, strategy = one_for_one, max_restarts = 5, interval = 60)

    let worker = new Worker(counter)
    supervise(worker, strategy = rest_for_one, max_restarts = 3, interval = 120)

    // 启动监督循环
    run_supervision_loop()

  // 监督循环
  be run_supervision_loop() =>
    while true do
      let event = await_supervisor_event()
      match event {
        case e: ActorCrashed =>
          handle_crash(e)
        case e: ActorNormalExit =>
          handle_exit(e)
        case e: ActorTimeout =>
          handle_timeout(e)
      }
    end
}
```

#### 3.3.2 监督策略

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| `one_for_one` | 只重启失败的 Actor | 独立工作者 |
| `one_for_all` | 重启所有子 Actor | 状态共享的工作者组 |
| `rest_for_one` | 重启失败的 Actor 及其之后的所有兄弟 | 顺序依赖的工作者 |
| `supervisor` | 子监督者管理下级 | 分层架构 |

#### 3.3.3 跨组件监督协议

监督树可以跨 Wasm 组件边界。跨组件监督通过以下协议实现：

```
┌─────────────────────────────────────────────────────────────┐
│              跨组件监督树                                    │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  组件A (Wasm)                    组件B (Wasm)               │
│  ┌─────────────┐                  ┌─────────────┐          │
│  │ Root Superv.│                  │ Worker Actor│          │
│  │  (策略: ...)│                  │  (工作者)   │          │
│  └─────────────┘                  └─────────────┘          │
│         │                                ▲                  │
│         │ 1. 启动远程 Actor              │                  │
│         │ ──────────────────────────────▶│                  │
│         │                                │                  │
│         │ 2. 注册跨组件监督              │                  │
│         │ ──────────────────────────────▶│                  │
│         │                                │                  │
│         │ 3. Worker 崩溃                 │                  │
│         │ ◀──────────────────────────────│                  │
│         │  (退出通知)                    │                  │
│         │                                │                  │
│         │ 4. 根据策略重启                │                  │
│         │ ──────────────────────────────▶│                  │
│         │  (重新实例化 + 状态恢复)       │                  │
│         │                                │                  │
└─────────────────────────────────────────────────────────────┘
```

跨组件监督状态恢复：
- Actor 状态通过 Wasm GC 的跨堆引用机制持久化
- 崩溃时序列化 Actor 状态到共享内存
- 重启时从共享内存反序列化状态

| 环境 | 调度模式 | 说明 |
|------|----------|------|

### 3.5 垃圾回收

#### 3.5.1 GC 策略选择

**决策：使用 Wasm GC（Cheney 半空间复制），而非 Pony 的 ORCA 协议。**

原因：
1. Pony 的 ORCA（标记-清除 + 循环引用检测）与 Wasm 内存模型不兼容
2. Wasmtime 47 已默认启用 Wasm GC（2026-07-20 发布）
3. Wasm GC 提供跨堆引用支持，适合 Actor 隔离模型
4. Wasm GC 暂停时间与堆大小成线性关系，可预测

#### 4.2.2 Channel

```pony
// 消息通道：类型安全的消息传递
actor Channel[T]() {
  var queue: Queue[T] = Queue[T]()
  var consumers: Array[Reply[T]] = Array[Reply[T]]()
  const BUFFER_SIZE: U32 = 256

  fun is_full(): Boolean =>
    queue.size >= BUFFER_SIZE

  fun is_empty(): Boolean =>
    queue.size == 0

  fun offer(val item: T): Boolean =>
    if not is_full() then
      queue.push(item)
      wake_one_consumer()
      true
    else
      false
    end

  fun take(ref reply: Reply[T]) =>
    if queue.size > 0 then
      reply(queue.pop())
    else
      consumers.push(reply)
    end
}
```

### 5.1 编译器 (ponyppc)

#### 5.1.1 技术选型

| 选项 | 优点 | 缺点 | 评估 |
|------|------|------|------|
| C | 零依赖、极高性能、跨平台、调试简单、Wasm 生态成熟 | 内存手动管理、无类型安全 | ✅ 首选 |
| C++ | 成熟、Pony 参考实现用 C++ | 内存安全、构建复杂 | ⚠️ 备选 |
| Rust | 内存安全、编译速度快、Wasm 生态好 | 学习曲线 | ⚠️ 备选 |
| Go | 快速开发、并发友好 | 性能、GC 暂停 | ❌ 不推荐 |
| Pony | 自举可行、Actor 原生 | 生态弱、自举风险 | ⚠️ 长期目标 |

**决策：编译器使用 C 语言实现。** 理由：
- 零依赖——不依赖任何运行时库
- 极高性能——系统级语言，与 Wasm 运行时同层
- 跨平台——单一 C 编译器即可跨平台
- 调试简单——GDB/Lldb 原生支持
- Wasm 互操作成熟——Wasmtime C API、Wasmer C API
- 与 Pony 生态一致——Pony 社区习惯 C 工具链

## 七、安全模型

### 7.1 威胁模型

| 威胁 | 说明 | 缓解措施 |
|------|------|----------|
| 内存越界 | 读取/写入超出边界 | Wasm 线性内存 + Wasm GC 边界检查 |
| 类型混淆 | 不同类型数据的错误转换 | 编译时类型检查 + 运行时类型标记 |
| Actor 间数据泄露 | 一个 Actor 访问另一个 Actor 的私有数据 | 引用能力 + 组件隔离 |
| 资源耗尽 | Actor 恶意消耗 CPU/内存 | gas 计数 + 内存限制 |
| 消息注入 | 伪造消息 | 消息 ID + 签名验证 |
| 供应链攻击 | 恶意依赖包 | 包签名验证 + 锁文件 |

    strategy = one_for_one,
    max_restarts = 5,
    interval = 60
  )

  new create() =>
    // 本地 Actor
    let local = new LocalWorker()

      host = "node2.ponypp.internal",

### 9.4 WIT 接口版本管理

```
interface counter.v1 {
  action create(initial: u64) -> u32
  action increment(id: u32)
  action get(id: u32) -> u64
}

interface counter.v2 {
  // 向后兼容 v1
  action create(initial: u64) -> u32
  action increment(id: u32)
  action get(id: u32) -> u64
  // 新增
  action reset(id: u32)
  action get_many(ids: list<u32>) -> list<u64>
}
```

版本兼容性规则：
- 新接口可添加方法（向后兼容）
- 不可删除或修改现有方法（破坏兼容）
- 不可修改现有方法的参数/返回值类型
- 版本不匹配时运行时拒绝加载

## 十六、总结

Pony++ 旨在融合三大技术优势：

1. **Pony 的引用能力** — 编译时消除数据竞争
2. **Erlang 的监督树** — 运行时容错
3. **WebAssembly 的沙箱** — 跨平台部署

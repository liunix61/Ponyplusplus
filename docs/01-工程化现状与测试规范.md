# Pony++ 编译器 — 工程化现状与测试规范

> 日期: 2026-09-18 | 分支: main (7bea2f4+)

## 1. 测试资产全景

| 体系 | 数量 | 入口 | 状态 |
|---|---|---|---|
| C 测试 (tests/*.c) | 10 | `make test`（wildcard 自动发现，失败即停） | ✅ 全绿 |
| gtest (tests/gtest_*.cpp) | 175 | `make gtest`（cmake build-cmake + ctest -j4） | ✅ **175/175 100% PASS (129.9s, 2026-09-18 实测)** |
| 统一回归 | 185 | `make regression` 或 `bash scripts/regression.sh` | ✅ |

C 测试清单: test_capabilities / test_codegen / test_e2e / test_lexer / test_parser / test_typecheck / test_types / test_wasm / test_wasm_e2e / test_wit

## 2. make targets（工程化自动化）

| 命令 | 作用 |
|---|---|
| `make test` | C 测试全量（tests/*.c） |
| `make gtest` | cmake 重构建 + ctest 175 gtest |
| `make regression` | **统一回归**: 清理(/tmp+*.gcov归位)→C测试→gtest→汇总报告 build/regression_report.txt |
| `make matrix` | regression + sanitizer 矩阵(asan/ubsan CFLAGS 注入) |
| `make coverage` | build-cov(--coverage) 构建+gcovr HTML → build-cov/coverage.html |
| `bash scripts/regression.sh --quick` | 仅 C 测试快速回归 |
| `bash scripts/regression.sh --cov` | 已有 build-cov 时重算覆盖率 |

## 3. 依赖修复（2026-09-18）

- GTest include: ~~nanoapi/build/_deps 跨项目路径~~ → **third_party/gtest/include**（已 vendor，跨项目耦合解除）
- GTest lib: third_party/gtest/lib（本地静态库，系统 GCC libstdc++）
- gcov 产物: 根目录 *.gcov 由 regression 阶段0 自动归位 build-cov/

## 4. 提交规范

- 回归全绿才提交: `make regression`（185 测试）为编译器变更的最低门禁
- codegen/parser/typecheck 变更后: 还需回归 nanonode（`ponybuild test` s6-s32）与 ponydb/ponypi 等下游项目抽查
- gtest 失败时查: build/ctest_last.log + build/test_<name>.log
- commit message: `fix(codegen): ...` / `feat(parser): ...` / `docs: ...`

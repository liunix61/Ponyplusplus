## 1. 定位与读者

### 1.1 目标定位

《Pony++ 程序设计语言》是一本**权威 + 入门友好**的 Pony++ 语言教科书，目标：

| 维度 | 定位 |
|------|------|
| 权威性 | 官方参考手册 + 语言规范权威解读 |
| 入门性 | 零基础读者可在 2-4 周内掌握核心 |
| 实用性 | 每章配套可运行 examples，边学边练 |
| 双语 | 中文为主 + 关键术语英文对照 |
| 形态 | Markdown 源 + PDF/EPUB 出版 + 在线版 |

### 1.2 目标读者

| 读者 | 痛点 | 本书如何解决 |
|------|------|------------|
| 有 C/C++ 基础的新手 | 想学新语言但不知道从哪入手 | 第1-4章从变量、控制流、函数讲起，类 C 语法平滑迁移 |
| 中级开发者 | 熟悉并发但不知道 Actor 模型 | 第5-8章深入 Actor、能力、并发、容错 |
| 后端开发者 | 想构建云原生服务 | 第9-14章覆盖标准库、IO、Web、组件模型 |
| 嵌入式开发者 | 想在 MCU 上写并发程序 | 第13章 MCU 嵌入式专章 |
| 研究员/架构师 | 想深入语言设计 | 附录：能力系统、监督树、Wasm 组件模型深入剖析 |

### 1.3 不服务的读者

- 只想查 API 的开发者（用 API 手册即可）
- 完全无编程基础的入门者（先用《Python 编程》）

## 2. 风格融合策略

### 2.1 《C 程序设计语言》（K&R）借鉴点

| K&R 特点 | 本书如何采用 |
|---------|------------|
| **代码先于解释** | 每章开头先给一个完整可运行的程序，再逐步解构 |
| **最小可运行示例** | 每个概念都配套 5-20 行最短代码 |
| **概念驱动** | 先讲"为什么需要 X"，再讲"X 是什么"，最后"怎么用 X" |
| **术语严格一致** | 全文术语表附录 + 每章首定义术语 |
| **示例即规范** | 书中所有代码可直接编译运行 |
| **简洁精炼** | 每节控制 3-5 页，避免冗长 |
| **习题即扩展** | 每章末 3-5 道练习题，引导读者改写代码 |

### 2.2 《C++ Prime Plus》借鉴点

| Prime Plus 特点 | 本书如何采用 |
|-----------------|------------|
| **循序渐进** | 章节顺序严格按依赖关系，不跳跃 |
| **每章末小项目** | 每章末有"本章实战"小项目（非玩具） |
| **实用优先** | 优先讲"日常最常用"的内容，冷僻功能放附录 |
| **大量实例** | 每节 2-4 个不同角度的实例 |
| **常见错误提示** | 每章"陷阱与误区"小节 |
| **术语中英对照** | 关键术语首次出现给出英文 + 中文 |
| **学习路径指引** | 每章末"下一步去哪里" |

### 2.3 融合原则

1. **K&R 的"最小可运行" + Prime Plus 的"循序渐进"** = 每章开头一个最小示例，章节顺序严格递进
2. **K&R 的"概念驱动" + Prime Plus 的"实用优先"** = 先讲日常最常遇到的场景，再深入原理
3. **K&R 的"简洁精炼" + Prime Plus 的"大量实例"** = 正文简洁，实例丰富（每个概念 2-4 个实例）
4. **K&R 的"习题" + Prime Plus 的"小项目"** = 每章既有习题（改写代码），又有小项目（完整程序）
5. **Pony++ 特色突出** = 能力系统、监督树、Actor 模型、Wasm 组件模型每章有专节

## 4. 单章写作模板

每章严格遵循以下结构（K&R 风格 + Prime Plus 风格融合）：

```
第 X 章  标题
   1. 本节学习目标（3-5 行）
   2. 本节概念地图（图）
   3. 完整可运行示例（先给）
       └─ 示例代码（带注释）
       └─ 预期输出
       └─ 编译/运行命令
   4. 概念详解（按小节拆分）
       4.1 子概念 A
           - 为什么需要 A（场景）
           - A 是什么（定义）
           - 怎么用 A（代码）
           - 多个实例（2-4 个）
           - 常见错误
       4.2 子概念 B
       ...
   5. 本章陷阱与误区
   6. 本章实战：小项目（完整程序）
   7. 习题（3-5 道，含答案在附录 I）
   8. 下一步（指向下一章或附录）
```

## 5. 单节写作规范

### 5.1 节标题格式

```
X.Y  子概念标题（中英对照）
```

例：`6.2  Actor 生命周期（Actor Lifecycle）`

### 5.2 代码块规范

每个代码块必须：

1. **顶部注释**：一句话说明
2. **行内注释**：关键行用 `//` 标注
3. **预期输出**：紧跟在代码块后
4. **编译命令**：紧跟在预期输出后

```
// 6.2.1 创建并启动一个 actor
actor Counter {
  var count: U32 = 0
  new create() => {
    print("Counter created")
  }
  be increment() => {
    count += 1
  }
}

// 预期输出:
// Counter created
//
// 编译: ./bin/ponyppc build counter.pny -o counter
// 运行: ./counter
```

### 5.3 概念解释三段式

每个概念严格按"为什么 → 是什么 → 怎么用"三段式：

```
**为什么需要**：一句话场景描述
**是什么**：正式定义 + 关键术语
**怎么用**：代码示例 + 预期输出
```

### 5.4 术语首现规范

术语首次出现用 `**术语**（English）` 加粗 + 英文：

```
Pony++ 采用 **Actor 模型**（Actor Model），...
```

### 5.5 图表规范

| 类型 | 工具 | 用途 |
|------|------|------|
| 概念图 | Mermaid | 章节开头 |
| 流程图 | Mermaid | 控制流 |
| 架构图 | Mermaid | 系统架构 |
| 状态图 | Mermaid | 状态机 |
| 序列图 | Mermaid | 消息传递 |

### 5.6 陷阱与误区格式

每章末"陷阱与误区"小节，统一格式：

```
### 陷阱 X.Y  <陷阱标题>

**错误代码**：
\```pony
// 错误示例
\```

**症状**：编译器报错 / 运行时错误 / 逻辑错误
**根因**：为什么会这样
**正确做法**：
\```pony
// 正确示例
\```

**预防**：一句话提醒
```

## 8. 质量保障

### 8.1 代码可运行验证

每个 example 必须：

1. `./bin/ponyppc build <file>` 编译通过
2. `./bin/ponyppc run <file>` 运行通过
3. 输出与书中"预期输出"完全一致

### 8.2 术语一致性检查

- 维护 `docs/glossary.md` 术语表
- 全书术语必须与术语表一致
- 术语首现必须用 `**术语**（English）` 格式

### 8.3 代码风格统一

- 统一 `.pny` 文件缩进、命名风格
- 统一注释风格（`//` 单行 + `/** */` 文档注释）
- 统一示例的"顶部说明 + 预期输出 + 编译命令"格式

### 8.4 审校清单

每章完成后必须过审校清单：

- [ ] 章节学习目标明确
- [ ] 概念地图清晰
- [ ] 最小可运行示例在开头
- [ ] 每节概念按"为什么→是什么→怎么用"展开
- [ ] 每节至少 2 个实例
- [ ] 术语首现加粗 + 英文对照
- [ ] 代码可编译运行
- [ ] 预期输出与代码一致
- [ ] 陷阱与误区小节
- [ ] 本章实战小项目
- [ ] 习题 3-5 道（难度分布合理）
- [ ] "下一步"指引下一章

## 10. 风险与应对

| 风险 | 影响 | 应对 |

## 二、核心模块详细审核 (设计文档第三章)

### 3.1 引用能力系统

| 设计要求 | 实际 | 差距 |
|---------|------|------|
| 6种能力 iso/trn/ref/val/box/tag | 运行时只有3种 (ISO/VAL/TAG) | ❌ 缺 trn/ref/box |
| sendable 属性标注 | 未实现 | ❌ |
| 跨组件序列化协议(能力标记1字节) | runtime.c 有 cap_mark | ✅ |
| 编译时能力验证拒绝非法发送 | capabilities.c 仅94行 | ⚠️ 简化版 |
| 能力转换规则 (iso→box消费语义等) | 未实现完整转换矩阵 | ❌ |

**关键差距**: 设计文档3.1.1定义6种引用能力，运行时序列化协议只实现了3种(PNY_CAP_ISO=0x01/PNY_CAP_VAL=0x02/PNY_CAP_TAG=0x03)。`trn`/`ref`/`box` 在运行时无对应标记。typecheck.c (332行) 自称"Phase 1 简化版"。

**影响**: 引用能力是Pony++的核心卖点——编译时消除数据竞争。仅3种能力意味着无法完整表达Pony的可变性语义：

- `trn` (转移引用): 无法区分"可变但可转移"的场景
- `ref` (本地可变引用): 无法在编译时拒绝跨Actor发送
- `box` (本地只读): 无法在编译时拒绝跨Actor发送

### 3.2 Actor 模型

| 设计要求 | 实际 | 评估 |
|---------|------|------|
| 生命周期 5状态(不存在/初始化/运行中/已停止/已崩溃) | INIT/RUNNING/STOPPING/STOPPED/RESTARTING | ⚠️ 缺 CRASHED |
| exactly-once 语义(消息ID+确认+重传+去重) | msg_id + 去重 | ⚠️ 无确认/重传 |
| 背压通知 | send返回-6 | ✅ |
| Actor寻址模型(组件ID+ActorID) | 仅ActorID | ⚠️ 无组件维度 |

**关键差距**: 
1. 设计文档3.2.2定义了"已崩溃(待重启)"状态，实际ACTOR_STATE枚举无CRASHED
2. exactly-once只做了去重，没有实现设计要求的"未确认消息由发送方重传"

### 3.5 垃圾回收

| 设计要求 | 实际 | 评估 |
|---------|------|------|
| Cheney 半空间复制 | gc.c 实现 | ✅ |
| **每 Actor 独立堆** | ❌ 全局单堆 | ❌ |
| Wasm GC 集成 (Wasmtime 47) | 自研 Cheney，非 Wasm GC | ⚠️ |
| 跨 Actor 引用扫描 | 未实现 | ❌ |
| GC触发: 堆使用率>80% | gc_should_collect | ✅ |
| GC暂停 < 1ms (10MB堆) | 实测 2.3ms | ❌ 超2.3x |
| 无全局STW (仅涉及引用的Actor暂停) | 全局STW | ❌ |

**关键差距**: 设计文档3.5.2要求"每个Actor有独立Wasm GC堆"，实际是全局单堆Cheney复制GC。这是**架构级差距**。

设计要求的隔离模型:
```
Actor A 堆 (独立)  ← GC仅暂停A
Actor B 堆 (独立)  ← GC仅暂停B
跨Actor引用: Wasm GC external references
无全局STW
```

实际实现:
```
全局单堆 ← GC全局暂停所有Actor
```

## 十二、改进路线图建议

### 短期 (1-2周)

1. **补齐引用能力**: 在runtime.h中增加PNY_CAP_TRN/REF/BOX，更新序列化协议
2. **增加CRASHED状态**: ACTOR_STATE枚举增加CRASHED，实现崩溃→重启流程
3. **simple_one_for_one**: 补充第4种监督策略
4. **stdlib基础模块**: uuid/base64/hex/regex (每个约50-100行)
5. **消息吞吐优化**: 无锁MPMC队列替代mutex WorkDeque

### 中期 (2-4周)

6. **per-actor GC堆**: 每个Actor独立GCHeap，GC仅暂停单个Actor
7. **并发原语**: promise/future实现
8. **crypto模块**: SHA-256/CRC32 (用OpenSSL，不自研)
9. **覆盖率报告**: gcovr生成，目标>85%
10. **TSAN验证**: 全量测试跑ThreadSanitizer

### 长期 (1-2月)

11. **IDE插件**: VS Code语法高亮(TextMate语法)+DAP调试集成
12. **增量编译**: 文件级缓存+依赖图
13. **DWARF生成**: 编译器输出调试信息
14. **分布式完善**: TLS+分布式监督+消息签名
15. **降级模式**: 自动检测环境，切换M:N/Web Workers/单线程
